Description

The list of widgets a page can use. PageBuilder.widgets is this list, and PageBuilder.addWidget adds to it. PageRenderer and a server read the same list, so a page that only renders a builder's JSON has to register the same widgets. It has no DOM, so it can be imported on a server.

Basic Usage

Register a widget of your own, then look the widgets up by name:

import {
  addWidget,
  registryOf
} from 'kempo-ui/src/utils/pageWidgets.js';
addWidget({
  name: 'quote',
  title: 'Quote',
  category: 'content',
  tag: 'blockquote',
  content: {
    name: 'text',
    mode: 'text'
  },
  attributes: [{
    name: 'text',
    type: 'string',
    virtual: true,
    label: 'Quote'
  }]
});
const registry = registryOf();
console.log(registry.get('quote').title);

API

widgets

The array of widget definitions, in the order they are listed in the Add list. It starts with the widgets kempo-ui ships. Each definition has been through the same checks as addWidget, so it has every field below, with defaults for the ones that were not given.

addWidget(config)

config: Object

The widget definition. See The Widget Definition.

Returns: Object

The definition as it is stored. A widget with the same name is replaced; otherwise the new one goes at the end of widgets. It throws an Error that says what is wrong when a rule is broken (see Rules).

The stored definition has these defaults for what was not given: category is 'content', icon is 'help', description is '', keywords is [], slots is [] and children is {}. page becomes an array (one URL, a list of URLs, or empty), and each attribute without a type is a 'string'.

registryOf(list = widgets)

list: Array (optional)

The definitions to look up. Defaults to widgets.

Returns: Map

The definitions by name. This is the registry that renderPage, pageTree and the builder use.

The Widget Definition

A widget is { name, title, tag, ... }. These are its fields:

FieldWhat it is
nameThe type stored in the page's JSON. Lowercase letters, digits and hyphens, starting with a letter.
titleThe name shown in the Add list, the tree and the settings.
category, categoryTitleThe group in the Add list (content, media, layout, interactive, or any name). categoryTitle is the heading of a new category.
icon, iconSrcA kempo-ui icon name, or the path of an icon file.
iconRotationDegrees to turn the icon clockwise. A right facing icon with 90 points down.
description, keywordsShown in the Add list, and matched by its search.
tagThe element the page uses for it. Lowercase letters, digits and hyphens, starting with a letter.
pageModule URL(s) the page needs, for the elements the widget's markup uses. They are loaded on the page.
editor, editorTagA module URL for the element the builder shows the widget with, and that element's tag.
settings, settingsTagA module URL for the element the settings panel shows, and that element's tag.
attributesThe settings. A select with beside: 'name' is drawn on the same line as the number setting of that name, with no label of its own (a value and its unit).
slotsWhere other widgets go: [{ name, label }].
childrenWidgets a new one starts with: { slotName: ['type', ...] }.
sectiontrue for a part of another widget (a column, a tab). It is added from its parent's settings.
inlinetrue for a widget that sits in a line with others (a button, an icon). It is drawn inline-block; any other widget is a block, so its margin, padding and border apply.
hideStylesParts of the Styles tab the widget does not have, because it has its own setting for them: 'box' (margin, padding, corners, sides), 'background', 'textColour', 'align', 'id', 'classes'. They are left out of the tab, and anything stored for them is not written on the page.
keydownOptional function(event, { node, path, html }) for a key pressed in an editable part of the widget (data-pb-edit). path names the part and html is what is typed in it now, not stored yet. It returns null to leave the key alone, or { attrs, focus } to store those settings, draw the page again, and put the caret in the part at the focus path. The key's default is cancelled when it does.
displayThe display class the widget's first element gets, instead of d-b (or d-ib with inline). '' for none, for a widget that sets its own display, which d-b would override.
content{ name, mode }: the attribute that is the element's text, as 'html' (sanitized), 'text' (escaped) or 'raw' (as it is).
classes, styleFunctions of the attributes, returning kempo-css classes (an array) and an inline style (a string).
prepareOptional async function(node) run when a page is shown in the builder, for data that comes from outside the page (a picture's size, say). It resolves to null, or to a function(liveNode) that changes the live widget and returns true when it did. The builder then publishes the change.
renderfunction(node, ctx, info, definition) returning the widget's whole HTML. See renderPage for ctx.

The Page Builder docs describe the settings (attributes) and how the builder uses these fields.

Rules

addWidget throws an Error when:

  • name is not lowercase letters, digits and hyphens starting with a letter.
  • There is no title.
  • tag is not a valid name in the same form as name.
  • There is an editor module but no editorTag.
  • There is a settings module but no settingsTag.

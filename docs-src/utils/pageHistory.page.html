Description

Undo and redo for the Page Builder: two stacks of earlier and later pages, going at most limit steps back. Each step is a copy of the page as it was before a change. The history is kept in memory only, so a reload clears it.

The builder uses it. It does not look at what a step holds, so it works for anything you can copy.

Basic Usage

import PageHistory from 'kempo-ui/src/utils/pageHistory.js';
const history = new PageHistory();
let page = {
  title: 'One'
};
history.push(structuredClone(page));
page = {
  title: 'Two'
};
page = history.undo(structuredClone(page));
console.log(page.title);
page = history.redo(structuredClone(page));
console.log(page.title);

Constructor

new PageHistory(limit = 50)

limit: number (optional)

The most steps kept. When there are more, the oldest is dropped. Defaults to 50.

Properties

limit: number

The most steps kept.

past: Array

The earlier pages, the most recent last.

future: Array

The pages that were undone, the next one to redo last.

canUndo: boolean

true when there is a step to go back to.

canRedo: boolean

true when there is a step to go forward to.

Methods

push(snapshot)

Records the page as it was before a change. Any steps to redo are gone once the page changes, and the oldest step is dropped when there are more than limit.

undo(current)

current: any

The page as it is now. It is kept, so that redo can come back to it.

Returns: any | null

The page to go back to, or null when there is none.

redo(current)

current: any

The page as it is now. It is kept, so that undo can come back to it.

Returns: any | null

The page to go forward to, or null when there is none.

clear()

Forgets every step, past and future.

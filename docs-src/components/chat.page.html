Security Notes

A chat-room widget: scrollable history of messages above, a markdown input + Send button below. The input is a <k-markdown-editor> — users type markdown (with a Preview tab to see the rendered output before sending), and the message is rendered to HTML via the vendored marked parser (CommonMark + GFM, including tables and task lists). The rendered HTML runs through sanitizeHtml on its way into the message bubble so any inline HTML the user types is filtered against the allow-list — <script>, <iframe>, etc. are always stripped.

Basic Usage

The component fires a send event when the user submits. Listen for it and call chat.addMessage(...) for incoming replies. Outgoing messages are added automatically.

<k-chat id="basicChat"></k-chat>
<script>
  const chat = document.getElementById('basicChat');
  chat.addEventListener('send', (e) => {
    console.log('Sent:', e.detail.markdown);
    setTimeout(() => {
      chat.addMessage({
        type: 'incoming',
        html: 'Got it!',
        sender: 'Bot'
      });
    }, 500);
  });
</script>

Enter Behavior

By default the chat matches Slack/Discord/Messages: Enter sends, Shift+Enter inserts a newline. Add the enter-newline attribute to flip it — Enter inserts a newline, Shift+Enter sends.

<k-chat enter-newline></k-chat>

Message Status

Add show-status and outgoing messages get an iMessage-style status indicator below the bubble. The four statuses are sending, delivered, read, and failed. When the user submits, the message is added with status: 'sending'; advance it via chat.updateMessage(id, { status }) as the backend confirms.

The attribute takes one of two display modes:

  • show-status or show-status="text" — small grey text labels (Sending…, Delivered, Read, Not Delivered). Default mode.
  • show-status="icons" — spinner / check / double-check / error icons only.

Following iMessage convention, the indicator only renders on the most recent outgoing message — older delivered/read messages stay clean. sending and failed always show regardless of position so the user knows about in-flight or stuck messages immediately.

<k-chat id="ackChat" show-status></k-chat>
<script type="module">
  await customElements.whenDefined('k-chat');
  const chat = document.getElementById('ackChat');
  chat.addEventListener('send', async (e) => {
    // Simulate a server round-trip
    await new Promise(r => setTimeout(r, 800));
    chat.updateMessage(e.detail.id, {
      status: 'delivered'
    });
    await new Promise(r => setTimeout(r, 1200));
    chat.updateMessage(e.detail.id, {
      status: 'read'
    });
  });
</script>

Icon Mode

Pass show-status="icons" for compact icon-only badges (spinner / single check / double check / red error) instead of text labels — closer to WhatsApp / Telegram styling.

Input Types

The input attribute chooses what the user types in. The editors are only loaded when they are chosen, so a chat with a plain box does not download them.

inputThe user types inSent as
markdown-editorA <k-markdown-editor> with Write and Preview tabs and a formatting toolbarMarkdown, shown as rich text
html-editorAn <k-html-editor> with a rich text toolbarHTML
markdown (default)A plain box that grows with the text. What is typed is markdown, shown as rich text once sentMarkdown, shown as rich text
textA plain box that grows with the textPlain text, exactly as typed

In every case the message is sanitized, and the send event has the same detail. With html-editor, markdown holds the text without the formatting.

Markdown Editor

The default input (above) is a plain box, so it needs no attribute. For a box with Write and Preview tabs and a formatting toolbar, use input="markdown-editor". Its text is markdown, and it is shown as rich text in the chat once sent. Type **hi** and preview it before you send.

<k-chat input="markdown-editor" placeholder="Write a message" style="--window_min_height: 8rem; --window_max_height: 14rem"></k-chat>

Plain Text

Nothing is interpreted: **hi** shows up as typed, and HTML is escaped.

<k-chat input="text" placeholder="Plain text only"></k-chat>

Resizing

There is no drag handle by default: the message box grows with its text and the message window keeps the rest of the space. Two attributes add a handle. markdown-resize adds the handle under the "markdown-editor" input, so the input can be made taller (the message window gets shorter). resize adds a handle under the whole chat, so the chat itself grows and the input stays the same size. The demos show both.

<k-chat input="markdown-editor" markdown-resize style="--window_min_height: 8rem; --window_max_height: 14rem"></k-chat>
 
<k-chat resize style="--chat_height: 18rem"></k-chat>

Prompt API (Very Experimental)

VERY EXPERIMENTAL: DO NOT RELY ON THIS

Everything here that uses the browser's built-in AI (the Prompt API) is an experiment, and it is not useful yet. The model that ships with Chrome is tiny. In the author's testing it could not answer a single question correctly: it ignored its instructions, skipped tool calls, made up attributes and wrote wrong code. The code around it works (it sends messages, runs tools and shows replies), but do not expect correct answers, and do not put it in front of your users.

It needs a recent desktop Chrome with the on-device model available, and the first message downloads the model. This does not affect the rest of the chat: a chat you connect to a person, a server or a cloud model works as usual.

Add prompt-api and the chat becomes an interface to the browser's built-in language model (Chrome's Prompt API) through the promptApi utility. Every message the user sends is answered by the model, and the reply streams into the chat as it is written. The conversation is the model's memory: it sees every earlier message until you call clear().

The attribute's value is the URL of a text or markdown file holding the system prompt, which tells the model what its job is. Give it several URLs separated by spaces and the files are read in order and joined, so you can keep the model's job in one file and its knowledge (a product list, your docs) in others. Without a value (prompt-api alone) the model has no system prompt. The files are loaded, and the model session created, when the first message is sent; if the model still has to be downloaded the reply shows the progress.

Keep the files short. The browser's model can only read a few thousand tokens at once (about 6,000 in the Chrome versions reported so far; check session.inputQuota for yours), and that has to hold the system prompt and the conversation. Files that are too big make the chat show an error. The docs chat reads overview.txt, a short hand-written list of what each component and utility is for, because all the documentation together is far too big. The details of one component are fetched only when needed, see Looking Things Up.

Tools

Set the promptTools property to a list of functions the model may call, and it can act on the page, not just talk. Each tool has a name, a description the model reads to decide when to use it, an inputSchema (JSON Schema) for its arguments, and an execute function that does the work and returns a string telling the model what happened. In the example, ask the chat to switch to dark mode. The tool-call event fires each time the model uses a tool.

The tools are described to the model in its system prompt, and it asks for one by writing a TOOL_CALL line that the chat hides, runs your execute function, and gives the result back to the model so it can answer. This works with any model, because it does not need the browser's own tool calling (which Chrome's model did not use). The model is small, though, so it can still miss a call, or answer without making one: say in your system prompt when each tool should be used. To let the model edit something bigger than a setting, such as a page builder, see Editing a Document with Tools.

Pair it with show-status and the user's message goes from Sending to Delivered (the model started) to Read (the reply is complete), or Not Delivered if it failed. In a browser without the Prompt API the chat says so.

Very experimental, and not useful yet: in the author's testing the browser's built-in AI could not answer a single question correctly. See the warning at the top of this section. 
<k-chat id="aiChat" prompt-api="/media/kempo-helper.md /overview.txt"></k-chat>
<script type="module">
  import {
    setTheme
  } from '/src/utils/theme.js';
  await customElements.whenDefined('k-chat');
  const chat = document.getElementById('aiChat');
  chat.promptTools = [{
    name: 'setTheme',
    description: 'Changes the color theme of this page',
    inputSchema: {
      type: 'object',
      properties: {
        theme: {
          type: 'string',
          enum: ['light', 'dark', 'auto']
        }
      },
      required: ['theme']
    },
    execute: ({
      theme
    }) => {
      setTheme(theme);
      return `The theme is now ${theme}.`;
    }
  }];
  chat.addEventListener('tool-call', (e) => {
    console.log('The model called', e.detail.name, e.detail.arguments);
  });
</script>

Saving Conversations

Add persistent-id and the chat saves its messages in the browser (IndexedDB, which holds whole conversations where localStorage cannot) and brings them back after a reload. The value names a group of conversations: the most recent one in the group opens when the page loads, and several can be kept side by side. Use different values for different chats on the same site.

With prompt-api, the model remembers too: the first time you send a message after a reload, the saved turns are given to the model as the conversation so far. If a long conversation does not fit in the model's memory, the oldest turns are left out.

The chat keeps one conversation open at a time. newConversation() starts an empty one (the old one stays saved, and the model starts again without remembering it; the empty one stays the open one when the user goes to another page, until they send a message or open another conversation), loadConversation(id) opens a saved one, and listConversations() lists the group's conversations so you can build a picker, as below. Try it: send a message, reload the page, and it is still there.

<k-chat id="savedChat" prompt-api="/media/kempo-helper.md /overview.txt" persistent-id="docs-helper"></k-chat>
<k-combobox id="pastChats" placeholder="Past conversations"></k-combobox>
<button id="newChat">New conversation</button>
<script type="module">
  await customElements.whenDefined('k-chat');
  const chat = document.getElementById('savedChat');
  const picker = document.getElementById('pastChats');
  const refresh = async () => {
    picker.setOptions((await chat.listConversations()).map(c => ({
      label: c.title || 'Empty conversation',
      value: c.id
    })));
  };
  chat.addEventListener('conversation-change', refresh);
  chat.addEventListener('conversation-save', refresh);
  picker.addEventListener('select', e => chat.loadConversation(e.detail.value));
  document.getElementById('newChat').addEventListener('click', () => chat.newConversation());
  refresh();
</script>

It works without prompt-api too: any chat with a persistent-id saves the messages you add with addMessage() and the user's own. Add a welcome message only when chat.messages.length is 0 after the saved conversation has loaded (the conversation-change event), or it will be added again on every reload. Messages marked transient: true are never saved.

Saved in this browser only. The conversations are stored unencrypted, in the browser's storage for this site, and anyone using this browser profile can read them. Do not use persistent-id for conversations that hold secrets on a shared computer.

JavaScript Reference

Constructor

Extends ShadowComponent
new Chat()

Requirements

  • ShadowComponent
  • MarkdownEditor (the default input), HtmlEditor (input="html-editor"); each is only loaded when chosen
  • sanitizeHtml utility
  • promptApi utility (only used with prompt-api)
  • conversations utility (only used with persistent-id)

Properties

input: String

What the user types in: "markdown-editor" (default), "html-editor", "markdown" or "text". See Input Types. Any other value is treated as the default. Syncs to input attribute.

markdownResize: Boolean

Adds the drag handle under the "markdown-editor" input, so the user can make it taller. Off by default (no handle). Syncs to markdown-resize attribute.

resize: Boolean

Adds a drag handle under the whole chat: the message window grows or shrinks and the input keeps its size. Use --chat_height for the starting height. Off by default. Syncs to resize attribute.

enterNewline: Boolean

Inverts the default Enter-key behavior. Default is false (Slack-style: Enter sends, Shift+Enter inserts a newline). When true: Enter inserts a newline and Shift+Enter sends. Syncs to enter-newline attribute.

showStatus: String

Enables and configures the per-message status indicator. Possible values: null/empty (off, default), "text" (small grey labels — the default mode when the attribute is set without a value), or "icons" (spinner/check/double-check/error glyphs). The indicator only appears on the most recent outgoing message, except for sending and failed which always show. Outgoing messages submitted via the input start as sending — advance them via updateMessage(id, { status }) as the backend confirms. Syncs to show-status attribute.

debug: String

Very experimental, see the warning above. With prompt-api, records every step of the conversation with the model, kept with the saved conversation so it can be exported: the system prompt (and the tools described in it), your message, each message sent to the model, its raw reply (so you see a TOOL_CALL, or that there was none), each tool call with its arguments and result, the context used (inputUsage/inputQuota), the answer shown, and errors. Default off. debug="console" also prints each step to the browser console. Syncs to debug attribute. See exportConversation() and debugLog.

emptyMessage: String

Text shown in the middle of the message area while there are no messages, such as a hint of what the chat is for. It goes away with the first message. Default "" (nothing). Syncs to empty-message attribute. Not to be confused with placeholder, which is the text inside the input.

placeholder: String

Placeholder text for the input. Default "Type a message...". Syncs to placeholder attribute.

disabled: Boolean

When true, the input and Send button are disabled. Syncs to disabled attribute.

promptApi: String

Very experimental and not useful yet, see the warning above. Turns the chat into an interface to the browser's built-in language model. Default null (off). Set it to the URL of the file holding the system prompt, several URLs separated by spaces (read in order and joined), or an empty string for no system prompt. Changing it ends the current model session, so the next message starts a fresh conversation. Syncs to prompt-api attribute.

persistentId: String

Saves the conversation in IndexedDB and restores the most recent one of the group after a reload. The value is the name of the group, so it should be unique for each chat on the site. Default null (nothing is saved). Syncs to persistent-id attribute. See conversations.

conversationId: String (read-only)

The id of the conversation that is open, or null before anything was saved.

promptTools: Array

Very experimental, see the warning above. Functions the model can call when prompt-api is set. Default []. Each entry is { name, description, inputSchema, execute(args) }, where inputSchema is a JSON Schema for the arguments and execute returns (or resolves with) a string for the model. JavaScript only, there is no attribute. Changing it ends the current model session.

debugLog: String (read-only)

Everything recorded by debug for the open conversation, as one text.

messages: Array (read-only state)

The current array of messages. Each entry is { id, type, html, status, sender, markdown, transient, timestamp }. Don't mutate directly — use the public methods.

Methods

addMessage(msg): string

Append a message and return its id. msg object accepts { id, type, html, status, sender, markdown, transient, timestamp }. markdown is the source text, which is what the model is given for earlier turns; transient: true keeps the message out of the saved conversation; missing fields are filled in (auto-generated id, type defaults to "incoming", etc.). HTML is sanitized.

updateMessage(id, updates): boolean

Update an existing message's html, status, sender, or timestamp. Returns true if a message with that id was found.

removeMessage(id): boolean

Remove a message. Returns true if found.

clear(): void

Remove every message and delete the saved conversation. With prompt-api it also ends the model session, so the model forgets the conversation. To keep the saved conversation, use newConversation().

newConversation(): void

Starts an empty conversation (and a fresh model session). The one that was open stays saved.

loadConversation(id): Promise<boolean>

Opens a saved conversation. Resolves with false if there is no conversation with that id.

listConversations(): Promise<Array>

The saved conversations of this chat's persistent-id group, newest first, as { id, title, createdAt, updatedAt }. The title is the start of the first message.

renameConversation(id, title): Promise<boolean>

Gives a saved conversation a title of your choice (an empty title goes back to the automatic one, the start of the first message). It keeps its place in the list and keeps the title as the conversation goes on. Resolves with false if there is no conversation with that id.

exportConversation(id?): Promise<string | null>

A conversation (the open one by default, as it is right now) as one text to save to a file: its details, the messages, and the record kept by debug (what was sent to the model, its raw replies, the tool calls). Resolves with null if there is no such conversation.

deleteConversation(id): Promise<void>

Deletes a saved conversation. If it is the open one, a new empty conversation is started.

focus(): void

Puts the cursor in the input, whichever input type it is.

send(text?): string | null

Programmatically submit whatever is currently in the input, or text if you pass it (the input is then left alone, which suits buttons with a ready-made message). Returns the new outgoing message's id, or null if there was nothing to send.

Slots

Put your own controls (buttons, a label, a menu) in these slots. A slot takes no room until something is in it.

Events

send

Fires when the user submits. detail contains { id, html, markdown } — html is the rendered+sanitized output (the same string used in the bubble) and markdown is the raw source the user typed (with input="html-editor", the text without the formatting). The outgoing message is already in the conversation by the time the event fires — if you need to roll it back (e.g. on a network failure), call updateMessage(id, { status: 'failed' }) or removeMessage(id).

response

Only with prompt-api. Fires when the model has finished a reply. detail contains { id, html, markdown } of the incoming message.

conversation-change

Fires when a different conversation is open: a saved one was restored after a reload, or loadConversation(), newConversation() or clear() was called. detail contains { id } (null for an empty conversation).

conversation-save

Only with persistent-id. Fires after the conversation was saved, which happens shortly after its messages change. detail contains { id }. Refresh a list of conversations when it fires, as the example above does.

message-add

Fires whenever a message is added, by the user, by addMessage() or by the model. detail contains { message } (message.transient is true for notices and for a reply that is still being written).

tool-call

Only with prompt-api. Fires after the model called one of the promptTools and it finished. detail contains { name, arguments, result }.

error

Only with prompt-api. Fires when the system prompt file cannot be loaded, the model is unavailable, or a reply fails. detail contains { error }. The outgoing message is set to failed and the error is shown in the chat.

Security Notes

The frontend sanitization in this component is not a substitute for server-side sanitization.

Every message that enters the chat (whether from the user's editor, from addMessage(), or from updateMessage()) runs through sanitizeHtml before it is added to the DOM. That strips <script>, <style>, <iframe>, event-handler attributes, and unsafe URL schemes — but it only protects content that flows through this component.

If you persist messages on a server and rebroadcast them to other users, the server must independently sanitize before storing and again before sending. A determined attacker can submit raw HTTP without ever loading your client code.

Renders the page that Page Builder emits as a page. The element writes the page's HTML into itself, loads the modules its widgets need, and runs its scripts. It is plain HTML and not Lit, so the same markup can be written on a server.

The example below renders the page saved by the Page Builder demo. The example page does the same on its own.

Using it

Set value to a page. The element renders it, and fires render when the widgets are in place.

<k-page-renderer id="page"></k-page-renderer>
<script type="module">
  import '/kempo-ui/src/components/PageRenderer.js';
  const page = JSON.parse(localStorage.getItem('my-page') || 'null');
  if (page) document.getElementById('page').value = page;
</script>
NameDoes
valueThe page, as the builder emits it. Setting a new page replaces the old one.
render eventFired once the page is in the element. detail.value is the page.
PageRenderer.toHTML(value)The page's HTML as a string, for a page that is rendered without a browser.

The element renders the widgets registered in PageBuilder.widgets, so a widget added with PageBuilder.addWidget (or with addWidget from utils/pageWidgets.js) renders here too.

Rendering on a server

Import the utilities rather than the element. The element defines custom elements when it loads, and a server cannot do that. Both utilities have no DOM and no Lit.

import {
  renderPage
} from '/kempo-ui/src/utils/renderPage.js';
import {
  widgets,
  registryOf
} from '/kempo-ui/src/utils/pageWidgets.js';
const html = renderPage(pageJson.slots.default, registryOf(widgets));

Pass a sanitize function. kempo-ui's sanitizeHtml needs a browser DOM, so it cannot run on a server, and without a sanitizer the HTML of text widgets and table cells is written exactly as it was saved. Markdown text is escaped, and the HTML widget is written as it is on purpose, so neither goes through sanitize: only let people you trust edit an HTML widget.

const html = renderPage(pageJson.slots.default, registryOf(widgets), {
  sanitize: html => mySanitizer(html)
});

collectModules(nodes, registry) returns the modules the widgets need. Their URLs are made from import.meta.url, so on a server they are file: URLs. Map them to the URLs your site serves the files from before you put them in a page.

const scripts = collectModules(pageJson.slots.default, registryOf(widgets))
  .map(url => url.replace(/^.*\/src\//, '/kempo-ui/src/'));

Notes

  • The modules a page needs are loaded before its HTML is written, so the widgets upgrade as soon as they are shown.
  • Scripts in the page run. The element re-creates them, since a script written with innerHTML does not run.

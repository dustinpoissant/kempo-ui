Page Builder (<k-page-builder>)
Import: import 'kempo-ui/src/components/PageBuilder.js';
Docs: https://dustinpoissant.github.io/kempo-ui/components/page-builder.html

A controlled page editor: a control bar, the widget tree on the left, the page in an iframe in the middle and the settings of the selected widget on the right. It keeps nothing itself. `value` is the page, and every change is emitted, so the parent stores the JSON.

Details:
- the page is { attrs: { title, description }, slots: { default: [widget nodes] } }; a widget node is { id, type, attrs, slots: { [slot]: [nodes] } }
- a setting at its default is not stored in attrs; sections (columns, accordion sections, tabs) are nodes in their parent's slot and are edited from the parent's settings
- an attribute with `beside: 'name'` (a select, a unit) is drawn on the same line as the number attribute of that name, with no label of its own
- group settings: element, and height + heightUnit (px, rem, vh; 0 is automatic) so widgets that fill their container have something to fill, e.g. Tabs with fixedHeight (which then gets height: 100%) inside a group with a height
- an accordion section's "Open by default" is stored as attrs.open on the section; until any section sets it the first section starts open, and without "allow several open" opening one closes the others
- tabs settings: fixedHeight, hashRouting (address hash), persistentId (remembered tab), and "Default open tab" (attrs.active holds that tab's node id); each tab has a title (label), a name (attrs.name, what the hash and the remembered tab use, an id-based one when empty or duplicated) ; a tab-spacer (Add spacer, listed with the tabs and moved or removed like one) is a section of the tabs that renders a k-tab-spacer. The builder itself ignores hash routing and the remembered tab
- content-slider settings: controls, loop, minHeight + minHeightUnit (px, rem, vh; 0 is automatic, written as the min-height attribute), keyboardControls, globalControls (shown with keyboard controls on), Add slide, "Start on slide" (attrs.active holds that slide's node id, written as the index attribute) and a move/remove row per slide; each slide is a `slide` section (a plain div, one child of k-content-slider) with a default slot. The builder shows the slider with keyboard-controls="false" so the arrow keys keep editing text, and its arrows move between slides (the slider keeps hidden slides out of the page, so the frame remembers the shown one by the slide's widget id across redraws)
- icon widget settings (the k-icon features): Icon (name, from the picker), Source (src, the address of any SVG file, used instead of the icon), Direction (down, left, up) or Rotation (degrees, shown while no direction is set), Animation (spin, blink, pulse). A picker value of `src:path` is treated as a Source
- set `value` to show a page; setting the page it already shows does nothing and counts it as saved; setting a different page clears undo history
- the page is drawn in an iframe on the same origin, with the page's own stylesheets and the theme utility, so the site's light, dark or auto theme shows and follows changes; its widget modules are loaded there by address
- `templates` (array of { name, nodes }) is listed under Insert a template; the builder never stores templates: listen to `template-save` ({ name, nodes }) and `template-remove` ({ index }) and update `templates`
- `device` is 'desktop' (default), 'tablet' or 'phone'
- the columns of Columns each have a width for desktop (1024px and up), tablet (769 to 1023px) and mobile (768px and under): a simplest fraction of the width (6 of 12 is 1/2, and 12 of 12 is full width) or fill the space; mobile is full width by default, so columns stack on a phone. The column list uses icon buttons to move and remove a column. Columns has the kempo-css classes `row -mx` and each column `px`, so the content keeps a gutter from the page's edge
- the device previews are each a width inside their own breakpoint range (desktop at least 1024px, tablet 900px, phone 390px), so the widths shown are the ones visitors get
- narrow screens: when the builder's own width is at or below `mobile-width` (property `mobileWidth`, default 768) `mobile` is true and it shows one view at a time (`view`: 'tree', 'page' (default) or 'settings'; `setView(view)`), because the tree, page and settings do not fit side by side; the tree, settings and device controls are replaced by a group of three `kc-pb-view` controls (`view="tree|page|settings"`, icons for the tree, a phone and the settings) and the page fills the width; `toggleTree()` and `toggleSettings()` switch the view then; wide again, the three panels and the old controls return
- `dirty` is true while changes have not been saved or given back as `value`
- `stylesheets` (property, array of addresses, set before the builder is added to the page) are stylesheets the frame uses besides the ones of the page the builder is in, for a builder in an admin whose stylesheets are not the site's
- methods: requestSave() (emits saverequest, and does nothing else: no storing, no message, not counted as saved), markSaved(page) (counts the given page, or the one shown, as saved: call it with `detail.value` once the page is stored; changes made since stay unsaved, and the builder warns before the page is left and turns the save button green while there are any), reset() (back to the last saved page), undo(), redo() (up to 50 steps, kept in the browser), insert(name) (adds a widget after the selection), canAdd(name), setDevice(device), setView(view), toggleTree(), toggleSettings(), openInserter(), openShortcuts(), setEditorSetting(name, value)
- events: change ({ value }) on every change; saverequest ({ value }) when the person asks to save (Ctrl+S or the save button), which is where the page should be stored, the person told (Toast.success or Toast.error) and markSaved(detail.value) called; template-save; template-remove
- the save button is green while there are changes that have not been saved (the `dirty` state)
- the editor setting Confirm deletion is in the page settings panel (shown when nothing is selected); it is a preference of the person editing, so it is kept in localStorage under kempo-ui:page-builder and not in the page
- keyboard in a table cell: Enter moves into the same column of the next row, and on the last row adds a row below and moves into it,Shift+Enter is a new line in the cell, Ctrl (or Cmd)+Enter adds a column after the cell (after the columns it spans) and moves into it, Tab moves to the next cell; they are listed in the Keyboard shortcuts dialog
- keyboard: Ctrl+K add, Ctrl+S save, Ctrl+D duplicate, Ctrl+Z / Ctrl+Shift+Z undo and redo, Delete remove, Escape select parent, Alt+Shift+arrows move
- toolbar controls are kc-pb-* (tree, add, delete, duplicate, move-up, move-down, move-in, move-out, device, view, save, reset, settings, shortcuts, template-save, template-insert) plus kc-undo and kc-redo, in a k-control-bar that collapses into its More menu. Left: tree, [add, delete, duplicate], [undo, redo], [move up, move down, move into widget, move out of widget] (one group, so they collapse together). Center: [phone, tablet, desktop]. Right: a Templates menu (split, so its items collapse into the More menu one at a time), [save, reset], shortcuts, settings. The tree and settings buttons, Add and the Templates menu never collapse; [add, delete, duplicate] is a split group, so Delete and Duplicate collapse into the More menu on their own (medium priority) while Add stays. Highest collapse priority: [save, reset] and the device group; [undo, redo] is medium

Widgets (static):
- PageBuilder.widgets: the list of widget definitions; starts with the widgets the library ships (text, markdown, image, video, audio, file, photo-viewer, media-gallery, hero, embed, group, breakout, container, columns, spacer, divider, button, table, html, script, accordion, tabs, card, content-slider, show-more, icon; sections are accordion-item, tab-item, tab-spacer, column and slide)
- PageBuilder.addWidget(config): adds a widget or replaces the one with the same name; returns the stored widget. Throws with a reason when the config breaks a rule.
- config: name (required, lowercase, digits, hyphens), title (required), tag (required, the element the page uses), category ('content', 'media', 'layout', 'interactive' or any name with categoryTitle), icon or iconSrc, iconRotation (degrees to turn the icon clockwise, 90 turns a right facing icon to point down), description, keywords
- the three components, each a module path (a string), not a class: page (module(s) that define the elements the widget's markup uses on the real page), editor + editorTag (optional; the element the builder shows in the page instead, for editing in place; the module must define editorTag), settings + settingsTag (optional; the element the settings panel shows; without it the panel draws a field per attribute; the module must define settingsTag). The Text widget has no editor element: while the builder shows it, its markup is `contenteditable`, so it is typed into on the page. When it loses focus its HTML is sent as a change (only if it changed; Ctrl+S saves what is being typed first). Its settings have an Edit text button that opens the full rich text editor in a large dialog
- attributes: [{ name, type, label, hint, default, options, min, max, when, virtual }]; types string, text, number, boolean, select, url, image, video, audio, color, id, json, icon; `virtual` settings are not written as element attributes; an `icon` setting is a picker (k-icon-selector) whose value is a kempo icon name, or `src:` and the path of a custom SVG, which the widget's markup draws with `<k-icon>`
- styles: every widget except the pieces of a widget (sections, columns, tabs) takes a `styles` setting, written as kempo-css classes on the widget's first element, on the page and in the builder: `margin` and `padding` are `{ top, right, bottom, left }`, each '' (none), 'q' (¼ spacer), 'h' (½ spacer) or 'f' (1 spacer), giving `mt`, `mbq`, `plh`, ..., or combined `my`, `mx` and `m` when the sides match; `background` is a kempo background name (`primary`, `alt`, ...) and `alpha` its opacity from 0 to 100 (the one inline style); `textColour` is a kempo text colour name; `align` is `left`, `center` or `right` (`ta-*`); `corners` is a list of `tl`, `tr`, `bl`, `br` (all four is `r`); `sides` is a list of `top`, `right`, `bottom`, `left` (all four is `b`); `id` and `classes` are the widget's id and extra classes. The settings panel has two tabs: Widget (the widget's own settings) and Styles (these)
- extra controls: an element placed inside `k-page-builder` with `slot="left-end"` (after the left controls), `slot="center-start"` or `slot="center-end"` (either side of the centre controls) or `slot="right-start"` (before the right controls) appears in that spot of the bar. Each spot is one group, so its controls collapse into the "more" menu together; it stays as long as its most important control, the highest `priority` among them (a bare `priority` counts as 1, none counts as 0, and a negative one collapses before controls that have none, such as the builder's own unranked ones). Use a `kc-*` control (a `ButtonControl` subclass, say) so it looks like the rest and shows as a row in the menu (its `menu-text` slot). The controls of a spot are drawn like the controls of a group: the builder takes away their own border, radius and margin and puts a line between them (the last one is marked `data-pb-last`), so a control draws its look on its host, not with a border of its own. A spot only appears while it has a control. For example a site's delete-page control is `<button slot="right-start" class="btn">Delete page</button>`; a `kc-*` control works the same way
- page settings: with nothing selected the right panel shows the page's title and description, then whatever a site puts in the `page-settings` slot of the builder (`<div slot="page-settings">`, for its own fields such as a name or a template), then the Confirm deletion setting
- dialogs: the builder opens its dialogs (the code editor of the HTML and Script widgets, the text editor, the Add list, the templates) on the page with `Dialog.create`, so they are above everything on the page, such as a site's side navigation
- pickers: `PageBuilderFields.pickers` holds the picker for each `image`, `video`, `audio` and `icon` field, as functions of `{ id, value, change }` that return a template (`change(value, coalesce)` sets the field). The defaults are a URL text input (`image`, `video`, `audio`) and `k-icon-selector` (`icon`). A site replaces one by importing PageBuilderFields and setting `pickers.image`, `pickers.video`, `pickers.audio` or `pickers.icon` to its own function, e.g. a media library chooser or an icon search backed by its API; every field of that type in the builder then uses it, including the Photo viewer's photos. Each picker has its own page under components/page-builder/ (image, video, audio, icon) with the contract and an example
- slots: [{ name, label }] where other widgets go (default is the element's children); children: { slot: ['type', ...] } for the widgets a new one starts with
- content: { name, mode } the attribute that is the element's text (mode html, text or raw)
- section: true for a part of another widget (a column, a tab), left out of the Add list
- the Embed widget's iframe is inert in the builder (`pointer-events: none`, `tabindex="-1"`), because a cross-origin iframe swallows clicks and keyboard focus, so the widget could not be selected by clicking it and keys never reached the builder; on the page it works normally
- the Group widget's only own setting is its HTML element (`div`, `section`, `article`, `header`, `footer`, `aside`, `nav`); `main` is not offered, because a page has one `<main>` and it belongs to the template the page is drawn in, not to the page (an old `element: 'main'` is drawn as a `div`); use the Container widget (`div.container`, which kempo-css styles like `main`) to narrow content
- the Horizontal rule (`divider`) widget has its own Space above and Space below (`above`, `below`, a size or custom pixels), written as inline `margin-top` / `margin-bottom` with `!important`, because the margin classes of the Styles tab are `!important` too: a side with a Space chosen uses it, and a side left at None uses the Styles margin
- hideStyles: a list of parts of the Styles tab the widget does not have, because it has its own setting for them: `box` (margin, padding, corners, sides), `background` (with its opacity), `textColour`, `align`, `id`, `classes`; a hidden part is left out of the tab and what is stored for it is not written on the page; the Script hides everything but `id` (`box`, `background`, `textColour`, `align`, `classes`), because nothing of a script is drawn; the Button hides `background`, because its Color setting (`btn primary`...) is its whole look (background, text and border), while its text alignment, margin, padding and text colour come from the Styles tab
- the Script widget's JavaScript (`code`, used when there is no script file) is edited the same way, with `language="javascript"` and a Save JavaScript button; the button is off while a script file is set, with a note saying why, and there is no textarea; the HTML and Script settings share a CodeSettings base (utils: `pagebuilder/CodeSettings.js`: a subclass names `codeSetting`, `codeLanguage`, `codeTitle` and `codeSaveText` and calls `renderCode({ note, disabled })`), which a site's own code widget can extend
- the HTML widget's settings have an Open code editor button that opens `<k-code-editor language="html" controls="full">` in a dialog that nearly fills the screen (96vw by 94vh), and it is the only way to edit the markup; Save HTML stores the markup exactly as written (it is not sanitized: the widget is shown as it is), as one undo step, and Cancel keeps what was there
- the Table widget has a `responsive` setting (on by default, "Make responsive"): the table is wrapped in kempo-css's `<div class="table-wrapper">` (it scrolls sideways when the screen is too narrow for the table, instead of widening the page), and then the widget's builder marks and its Styles belong to that wrapper; turned off, the table is drawn on its own
- the Table widget keeps `rows` (a grid of cell HTML), `spans` (`{ "row.column": number }`, a cell that covers the columns after it; the covered cells are not drawn but keep their text), `widths` (a width per column, written as a colgroup) and `header`; the cell text is not typed in the settings (they only add or remove rows and columns, and set spans and widths): in the builder each cell is contenteditable, an empty one is kept a clickable size, and its HTML is stored when it loses focus
- an editable part of a widget (a table cell) is marked `contenteditable="true" data-pb-edit="<path in attrs>"` (`rows.1.0` is attrs.rows[1][0]) by the widget's `render` when `ctx.editor`; when it loses focus its sanitized HTML is stored at that path (`<br>` alone is stored as empty); the place has to exist already. `valueAt(attrs, path)` and `setValueAt(attrs, path, value)` in utils/pageTree.js read and write a path
- keydown(event, { node, path, html }): optional function on a widget definition for a key pressed in one of its editable parts (data-pb-edit); it returns null to leave the key alone, or { attrs, focus } to store those settings (the builder draws the page again as one undo step), and put the caret in the part at the `focus` path, and the key's default is cancelled; `html` is what is typed in the part now, which is not stored until it loses focus. The Table uses it for Enter and Ctrl+Enter in its cells
- display: the display class the widget's first element gets; by default `d-b` (`d-ib` with `inline: true`) so margin, padding and border apply; `''` for none, for a widget that sets its own display (Columns is flex, the Hero sets it inline, and a Script is not shown at all, which `d-b` would undo and show its code on the page), because `d-b` is `!important` and would override it
- the Fullscreen breakout (`breakout`) widget spreads a box to the full screen width from inside a narrower centred column (`k-main`, `main`, `.container`) with a negative margin, without moving it in the page; its width is `100vw` less `--left-panel-width` and `--right-panel-width` (set by `k-main` for asides that push), so it fills the space the page has; `contain` keeps its content in a `.container` column inside it; the Hero has a `breakout` setting that does the same, and a `fixed` setting (`background-attachment: fixed`, not supported on phones, which scroll the picture); the Container (`container`) widget is a div with the `container` class, for narrowing a full-width template; put a breakout in the page, not in a column of Columns; the width is `var(--page-width, 100vw)`, where `--page-width` is set on the root element by `utils/pageWidth.js` (loaded by the breakout and the hero, it is the page width without the scrollbar, kept up to date, because `100vw` includes the scrollbar and would scroll the page sideways), and `k-main` clips its sides as a safety
- classes(attrs), style(attrs), render(node, ctx, info, definition): functions for the markup (see utils/renderPage.txt)
- the page and the builder load the modules by address; a module defines its own elements with customElements.define

Not in this library: anything that needs a server or a site's own structure (storing the page, saved templates, page management, widgets that need a server). The site the builder is used in listens to saverequest, template-save and template-remove, adds its own controls to the bar (the extra slots) and its own widgets with PageBuilder.addWidget.

Example:
<k-page-builder id="builder" style="height: 80vh"></k-page-builder>
<script type="module">
  import 'kempo-ui/src/components/PageBuilder.js';
  import Toast from 'kempo-ui/src/components/Toast.js';
  const builder = document.getElementById('builder');
  builder.value = JSON.parse(localStorage.getItem('my-page') || 'null');
  builder.addEventListener('saverequest', event => {
    localStorage.setItem('my-page', JSON.stringify(event.detail.value));
    builder.markSaved(event.detail.value);
    Toast.success('Page saved');
  });
</script>

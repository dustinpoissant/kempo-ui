What It Does

Description

The page as the Page Builder shows it: an iframe holding the site's own stylesheets, with the page rendered into it in editor mode (every widget's element carries data-pb-id). This class owns that iframe. The builder gives it the tree and the ids to mark as selected, and it reports what the person did through the handlers.

The builder uses it. It is documented here so a site that extends the builder knows what the frame does, and it is not meant to be used on its own. It needs a browser.

The iframe is on the same origin, so the builder reads and writes its document directly. The widgets' modules are loaded by the iframe's own window (a script tag inside it), so their elements are defined there and upgrade.

Basic Usage

import PageFrame from 'kempo-ui/src/utils/pageFrame.js';
import {
  widgets,
  registryOf
} from 'kempo-ui/src/utils/pageWidgets.js';
const frame = new PageFrame(document.querySelector('iframe'), {
  onSelect: (id, {
    additive
  }) => frame.setSelection([id]),
  onBlank: () => frame.setSelection([]),
  onChange: (id, changes) => console.log(id, changes),
  onDrop: (id, place) => console.log(id, place),
  canDrop: () => true,
  restricted: () => false,
  onKeyDown: event => console.log(event.key),
  locate: () => null,
  nameOf: () => 'a widget'
});
await frame.ready;
await frame.render(page.slots.default, registryOf(widgets), []);

Constructor

new PageFrame(iframe, handlers)

iframe: HTMLIFrameElement

The iframe to draw the page in. The constructor gives it a document with the stylesheets of the page it is on, the editor's marks, and an empty root.

handlers: Object

See Handlers.

Handlers

  • onSelect(id, { additive }) — a widget was clicked. additive is true with Ctrl, Cmd or Shift held.
  • onBlank() — the page itself was clicked.
  • onChange(id, changes) — a widget's editor changed its settings (a pb-change event from the widget, or text edited on the page when it loses focus).
  • onDrop(id, place) — a widget was dropped. place is { parentId, slot, index }.
  • canDrop(id, parentId, slot) — whether the dragged widget may go in that list.
  • restricted(id) — whether the widget is moved from its parent's settings, not on the page (a section).
  • onKeyDown(event) — a key was pressed inside the page.
  • locate(id) — where a widget is: { parentId, slot, index }, or null.
  • nameOf(id) — what a widget is called in a drop label.

Properties

ready: Promise

Resolves once the iframe's document has loaded and the frame is listening to it. render waits for it too.

document: Document

The iframe's document.

window: Window

The iframe's window.

root: HTMLElement

The element the page is drawn in (#pb-root).

selection: Array<string>

The ids last given to setSelection.

Methods

render(nodes, registry, selection)

Returns: Promise

Draws the nodes (the page's list of widgets) with the registry they use, and marks the selection. It loads the modules the widgets need into the frame (once each) before it draws, writes the page with renderPage in editor mode, with sanitizeHtml as sanitize, and keeps the page where it was scrolled to. See What It Does for what it keeps from the page it replaces.

setSelection(ids)

Marks the widgets with these ids as selected: they get the class pb-selected, and the class is taken off the others. Each element gets a pb-selected event with detail.selected (true only when one widget is selected). A focused element that is not inside a selected widget is blurred, and the drag handle moves to the first selected widget.

showDropTarget(id, zone)

Shows where a widget being dragged somewhere else (in the tree) would go: the widget with that id gets the class pb-drop-before, pb-drop-after or pb-drop-inside to match zone ('before', 'after' or 'inside'). Any earlier target is cleared. Pass no id to clear them.

blurFocus()

Blurs the focused element in the frame, even when it is inside a shadow root.

scrollTo(id)

Scrolls the frame's page, up or down only, to bring the widget with that id into view. It does not scroll the page around the frame, which would push the left of the page out of view.

focusAfterRender(id, path)

Once the page has been drawn again, puts the caret at the end of the part of widget id marked data-pb-edit="path".

placeHandle()

Puts the drag handle above the first selected widget. It is hidden when nothing is selected, or the widget is restricted. The frame calls it itself when the selection changes and the page or the frame scrolls or resizes.

What It Does

Clicking

  • The first click selects the outermost widget under it. A click inside the selected widget selects the next one down towards what was clicked, so each click goes one level deeper. With Ctrl, Cmd or Shift it is the widget beside the selected ones (the same parent). Sections are not selected on their own: the widget they are part of is.
  • An accordion's heading, a tab and a content slider's arrow select the widget they belong to, and still work: that click is not cancelled.
  • A click on the page itself is cancelled and calls onBlank, so the browser does not put a caret in the nearest text.
  • A link or a form in the page cannot take the builder somewhere else: its click is cancelled.

Editing on the Page

  • An editable part of a widget (contenteditable, with data-pb-edit naming what it edits, or the widget's own element for a text widget) sends its HTML to onChange when it loses focus, sanitized with sanitizeHtml: { html } for a text widget's own element, and { [path]: html } for a part named by data-pb-edit. An emptied data-pb-edit part sends '', not the <br> the browser leaves behind.
  • Keys pressed in the page go to onKeyDown. Escape cancels a drag.

Keeping the Page's State Between Draws

Every change draws the page again. So that this does not close what the person opened, the frame remembers and restores:

  • The open sections of each accordion.
  • The active tab of each tabs widget.
  • The slide being shown in each content slider.

They are found by the widget's id, so a renamed tab stays open. If the setting for what starts open (a section's open by default, the default tab, the start slide) is what changed, the new default is shown instead.

Empty Places

A container with nothing in it says it is empty, with the widget's name. A closed accordion section and a tab that is not active are not shown when empty.

Dragging

The handle above the selected widget is dragged with the pointer. While it is, every place the widget may go (canDrop) is shown as an outlined box: a zone between the widgets of each list (the page and every container), and each empty container. The box under the pointer fills in, the page scrolls when the pointer is near its top or bottom edge, and letting go on a box calls onDrop. Letting go anywhere else cancels.

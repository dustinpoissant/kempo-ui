Page Builder

A page editor. Widgets are added, arranged and configured, and the page is kept as JSON: a tree of widgets that a backend can store, and that Page Renderer turns into a page. The builder keeps nothing itself. It is controlled: it shows the value it is given, and every change is sent back as a change event.

The demo below saves its page to localStorage under kempo-ui:page when you click Save (the button turns green while there are changes to save). Open the example page to see what it renders.

Using it

Import the element and give it a page. The builder keeps the page you are editing until you save it: it emits saverequest with the page, and that is where you store it, and then tell the builder with markSaved. Give it back a page as value whenever it should show something else.

<k-page-builder id="builder" style="height: 80vh"></k-page-builder>
<script type="module">
  import '/kempo-ui/src/components/PageBuilder.js';
  const builder = document.getElementById('builder');
  builder.value = JSON.parse(localStorage.getItem('my-page') || 'null');
  builder.addEventListener('save', event => {
    localStorage.setItem('my-page', JSON.stringify(event.detail.value));
  });
</script>

The page

The page is an object with its settings in attrs and its widgets in slots.default, in order.

{
  "attrs": {
    "title": "Welcome",
    "description": "The home page."
  },
  "slots": {
    "default": [{
      "id": "a1b2c3",
      "type": "text",
      "attrs": {
        "html": "<h2>Welcome</h2>"
      },
      "slots": {}
    }, {
      "id": "d4e5f6",
      "type": "row",
      "attrs": {},
      "slots": {
        "default": [{
          "id": "g7h8i9",
          "type": "column",
          "attrs": {
            "size": "8"
          },
          "slots": {
            "default": [{
              "id": "j1k2l3",
              "type": "text",
              "attrs": {
                "html": "<p>Main content.</p>"
              },
              "slots": {}
            }]
          }
        }, {
          "id": "m4n5o6",
          "type": "column",
          "attrs": {},
          "slots": {
            "default": []
          }
        }]
      }
    }]
  }
}
  • Each widget is { id, type, attrs, slots }. type is the widget's name, attrs its settings, and slots the widgets inside it, by slot name.
  • A setting that is at its default is not stored, so attrs holds only what was changed.
  • Sections (a column, an accordion section, a tab, a slide) are widgets in their parent's slot. They are added and ordered from the parent's settings, not dragged on the page. In an accordion's settings each section has an Open by default toggle; until one is set the first section starts open. The Tabs settings cover what the Tabs component can do: the default open tab, hash routing, a persistent ID and fixed height, for each tab a name, and an Add spacer button that puts a tab spacer in the list with the tabs. Fixed height needs a container with a height, so put the tabs in a Group and give the Group a height. The Content slider works the same way: Add slide in its settings, the slide it starts on, move or remove each slide, and the component's controls, loop, keyboard controls and global controls. The slider's arrows work on the page to move between the slides you are editing.
  • Text and HTML widgets hold their markup in attrs.html. The browser cleans it when it is edited, but a server must sanitize it before it is saved.

Properties and methods

NameDoes
valueThe page. Setting it shows that page. Setting the page it already shows does nothing, and counts it as saved.
templatesThe saved templates, as [{ name, nodes }], listed under Insert a template. The builder does not keep them: listen to template-save and template-remove.
devicedesktop (the default), tablet or phone: the width the page is shown at.
mobileWidthThe width in pixels at or below which the builder is narrow (the attribute is mobile-width, and the default is 768). It is the builder's own width, not the window's, so a builder in a narrow box is narrow too.
mobile, viewRead only. mobile is true while the builder is narrow, and view is the view it shows then: tree, page (the default) or settings.
stylesheetsAddresses of stylesheets the page is drawn with, besides the ones of the page the builder is in (which are always used). For a builder in an admin whose own stylesheets are not the site's. Set it before the builder is added to the page: the frame is built once.
dirtyRead only. True while there are changes that have not been saved or given back as value.

Call it once the page is stored, so the builder can keep track of unsaved changes: it warns before the page is left, and turns the save button green while there are any.
reset()Puts the page back to how it was last saved.
undo(), redo()Steps back and forward through the changes (up to 50, kept in the browser).
insert(name), canAdd(name)Adds a widget after the selection, or checks whether it can go there.
setDevice(device), setView(view), toggleTree(), toggleSettings(), openInserter()What the toolbar does, for your own buttons.

Events

EventWhen, and what detail holds
changeEvery change. detail.value is the page.
saverequestThe person asked to save (Ctrl+S, or the save button). detail.value is the page. The builder does nothing else: store the page, tell the person how it went (Toast.success or Toast.error), and call markSaved(event.detail.value) once it is stored.
template-saveA selection was named as a template. detail is { name, nodes }.
template-removeA template was deleted from the list. detail is { index }.

Adding widgets

PageBuilder.widgets is the list of widgets the builder offers. It starts with the widgets the library ships (see below). PageBuilder.addWidget(config) adds one, or replaces the widget with the same name. A widget has three components, each a module that defines its element:

  • page: the element the widget uses on the real page. The page and the builder both load it.
  • editor, optional: an element the builder shows in the page instead, so the widget can be edited where it is drawn (a rich text box, say). The Text widget has no editor element: while the builder shows it, its markup is contenteditable, so it is typed into on the page. When it loses focus its HTML is sent as a change, if it changed. Its settings have an Edit text button that opens the full rich text editor in a large dialog.
  • settings, optional: the element the settings panel shows for the widget. Without one, the panel draws a field for each attribute.

They are module paths rather than classes, because the builder's page is a separate document and can only load a module by its address.

import PageBuilder from '/kempo-ui/src/components/PageBuilder.js';
PageBuilder.addWidget({
  name: 'callout',
  title: 'Callout',
  category: 'content',
  icon: 'star',
  description: 'A boxed message that draws attention.',
  keywords: ['notice', 'alert'],
  tag: 'my-callout',
  page: '/my-site/components/Callout.js',
  editor: '/my-site/components/CalloutEditor.js',
  editorTag: 'my-callout-editor',
  settings: '/my-site/components/CalloutSettings.js',
  settingsTag: 'my-callout-settings',
  attributes: [{
    name: 'tone',
    type: 'select',
    label: 'Tone',
    default: 'info',
    options: [{
      value: 'info',
      label: 'Information'
    }, {
      value: 'warning',
      label: 'Warning'
    }]
  }, {
    name: 'message',
    type: 'text',
    virtual: true,
    label: 'Message'
  }],
  content: {
    name: 'message',
    mode: 'text'
  },
  slots: [{
    name: 'default',
    label: 'Content'
  }]
});
FieldMeaning
name, title, tagRequired. The type stored in the page (lowercase letters, digits and hyphens), its name in the Add list and tree, and the element the page uses.
category, categoryTitleThe group in the Add list: text, media, layout, content, interactive, or a new name with a categoryTitle.
icon, iconSrc, iconRotation, description, keywordsShown in the Add list. iconRotation turns the icon clockwise by that many degrees (90 turns a right facing icon to point down). keywords are matched by search.
pageThe module (or modules) that define the elements the widget's markup uses on the page.
editor, editorTagThe module, and the tag it defines, of the element the builder shows instead. Both are needed together.
settings, settingsTagThe module, and the tag it defines, of the settings element. Both are needed together.
attributesThe settings: { name, type, label, hint, default, options, min, max, when, virtual }. Types are string, text, number, boolean, select, url, image, color, id and json. A virtual setting is kept in the page but not written as an attribute, because the widget's markup (its classes, style, content or render) uses it.
slots, childrenWhere other widgets go, as [{ name, label }]. children gives the widgets a new one starts with, such as { default: ['column', 'column'] }.
contentThe attribute that is the element's text: { name, mode }, where mode is html (cleaned), text (escaped) or raw.
sectiontrue for a part of another widget (a column or a tab). Sections are left out of the Add list.
classes, style, renderFunctions for the markup: kempo-css classes, an inline style, or the whole HTML of the widget. See Page Renderer.

HTML

The HTML widget shows markup exactly as it is written, so only write markup you trust. Its settings have an Open code editor button, which opens the full code editor (syntax colors, find and replace, formatting, a minimap) in a dialog that nearly fills the screen. Save HTML stores what is in the editor untouched, and Cancel leaves the widget as it was. The Script widget's JavaScript is written the same way, in the code editor with JavaScript colors, when it has no script file (with a file set, the button is off, because the code is not used).

Table

The Table widget is typed on the page: click it to select it, then click a cell and type, as in a document. Tab moves to the next cell, Enter adds a row below and moves into the same column of it, Shift + Enter is a new line in the same cell, and Ctrl + Enter adds a column after the cell and moves into it. The cells are always big enough to click into, even when they are empty. The settings of the table are the things that are not text: whether the first row is a heading, Make responsive (on by default: the table is put in a table-wrapper box, which scrolls sideways when the screen is too narrow for the table instead of making the whole page wider, and the widget's Styles go on that box), adding and removing rows and columns, how many columns each cell spans (a cell that spans covers the ones after it, and their text is kept and comes back if the span is set back to 1), and the width of each column.

Fullscreen breakout and Container

A page is drawn inside its template's column: k-main, main or a .container, no wider than --container_width. Fullscreen breakout is a box that spreads to the full width of the screen from inside that column. It stays where it is in the page, in the order of the widgets: it is pulled out to the sides with a negative margin, nothing is moved. Its Styles give it a background, and Keep the content in a column keeps what is inside it as wide as the page column, so a full width band can have a normal width heading. The Hero has the same thing as its Fullscreen breakout setting. The Hero also has a Fixed background setting, which keeps its picture still while the page scrolls over it (background-attachment: fixed; phones that do not support it scroll the picture with the page).

It sizes itself from the width of the page, less the side panels a k-main makes room for (--left-panel-width and --right-panel-width), so it fills the space the page has when an aside is pushing the content. It needs to be in a column that is centred in the space it has, as k-main, main and .container are, and so belongs in the page itself, not in a column of Columns. The width of the page comes from --page-width on the root element, which utils/pageWidth.js sets to the page's width without its scrollbar and keeps up to date (the widget loads it); 100vw includes the scrollbar in most browsers and would make the page scroll sideways. k-main also clips its sides, as a safety.

A page has one <main>, and it belongs to the template the page is drawn in, so the Group widget's HTML element list does not offer main. Container does the opposite: a box with the container class, a centred column no wider than the page column. Use it to narrow content on a page whose template is full width (a k-main with full-width, for example).

Adding controls to the bar

A site can add its own controls, such as a delete-page or a publish button, to the toolbar. Put them inside the builder with a slot that names their place: left-end (after the left controls), center-start and center-end (either side of the centre controls), or right-start (before the right controls). A place only appears while it has a control, and it collapses into the "more" menu with its controls when the toolbar is narrow. A place is one group, so its controls collapse together. It stays as long as its most important control: give a control a priority (a bare priority counts as 1) and the place has the highest one among its controls. A control with none counts as 0, like the builder's own unranked controls, which then go in order from the right; a negative priority collapses before all of them. Controls that extend ButtonControl look like the rest of the bar, and show their menu-text slot as a row in the menu.

<k-page-builder id="builder" style="height: 80vh">
  <button slot="right-start" class="btn" id="copy-json">Copy JSON</button>
</k-page-builder>
<script type="module">
  document.getElementById('copy-json').addEventListener('click', () => navigator.clipboard.writeText(JSON.stringify(builder.value)));
</script>

The Copy JSON button in the demo above is added this way.

Adding fields to the page settings

With nothing selected, the right panel shows the page's own settings: its title and description. A site adds its own fields there (a name, a template, who made the page) by putting them inside the builder with slot="page-settings". They are shown below the description, only while nothing is selected, and are the site's to read and save.

<k-page-builder>
  <div slot="page-settings">
    <label for="name">Name</label>
    <input id="name" type="text">
  </div>
</k-page-builder>

Pickers

Some settings choose a file rather than take typed text: a picture, a video, an audio file or an icon. Each is drawn by a picker, and a site replaces a picker with its own (a media library, say) by setting it on PageBuilderFields: pickers.image, pickers.video, pickers.audio or pickers.icon. Each page below has the widget's settings, the picker's contract and an example.

  • Image picker: pictures, including the Hero background, the Video poster, each Photo viewer photo and the poster, cover art and thumbnail of each Media gallery item.
  • Video picker: the Video widget's address, and a Media gallery item that is a video.
  • Audio picker: the Audio widget's address, and a Media gallery item that is audio.
  • Icon picker: the icons on the Icon, Button, File, Accordion section and Tab widgets.

Styles

The settings panel of a widget has two tabs. Widget holds the widget's own settings. Styles sets how the widget is laid out and drawn, with kempo-css classes: its margin (the space outside it) and padding (the space inside it), each per side as ¼, ½ or 1 spacer; a background, with its opacity; a text colour; the text alignment (left, center or right); which corners are rounded; which sides have a border; and an id and extra classes. Each is applied to the widget's own element, on the page and in the builder. The pieces of another widget (a column, an accordion section, a tab) have no Styles tab, because their parent lays them out. A widget that has its own setting for one of these can leave it out of its tab: the Button has no background there, because its Color is the whole look of the button (its text and border change with the background, which a plain background class would not do), and its text alignment is the Text alignment of the Styles tab. The Script draws nothing, so its Styles tab has only the ID.

On a narrow screen

The widget tree, the page and the settings do not fit side by side on a phone, so a narrow builder (768px wide or less, which mobile-width changes) shows one of them at a time. The tree, settings and device buttons are replaced by a group of three that looks like them: the widget tree, the page (a phone) and the settings. Each shows only its own view, and the page fills the width. When the builder is wide again, everything comes back as it was.

Keyboard

Ctrl+K adds a widget, Ctrl+S saves, Ctrl+D duplicates, Ctrl+Z and Ctrl+Shift+Z undo and redo, Delete removes the selected widget, and Escape selects the parent. Alt+Shift with an arrow key moves the selection. The shortcuts button in the toolbar lists them all.

What is not here yet

  • Storing the page, saved templates and anything else that needs a server belong to the site the builder is used in: it listens to saverequest, template-save and template-remove, and adds its own controls to the bar (the extra slots above).
  • Widgets that need a server are the site's to add, with addWidget.

Accessibility

A round chat button that floats in a corner of the page (a floating action button). Clicking it opens a <k-chat> in a popup above it (or below it, when the button is at the top), and the button's icon turns into a chevron pointing away from the screen edge (down at the bottom, up at the top) to show that clicking it again minimizes the chat. When a message arrives while the chat is minimized the button wiggles and pulses between the primary color and red, with an "unread message" icon, until the chat is opened.

It is not tied to a language model. The chat inside is a normal <k-chat> (reachable as bubble.chat), so it can be a person at your company answering customers, a bot, an LLM you connect (see Connecting an LLM), or the browser's built-in model with the prompt-api attribute (very experimental and not useful yet, see the warning). With persistent-id, conversations are saved, and opening the bubble offers to continue a saved one, start a new one, or delete an old one.

On this page every bubble sits in a dashed box so it does not leave the example. In your page it floats in the corner of the window.

Basic Usage

The component fires the same send event as <k-chat>. Send what the user wrote to your server, and show the answers with bubble.chat.addMessage(). Try minimizing the chat after sending a message: the answer arrives 1.5 seconds later and the button asks for attention.

<k-chat-bubble id="supportBubble" heading="Support" empty-message="Ask us anything. A real person will answer."></k-chat-bubble>
<script type="module">
  await customElements.whenDefined('k-chat-bubble');
  const bubble = document.getElementById('supportBubble');
  bubble.addEventListener('send', (e) => {
    // Send e.detail.markdown to your server, then show the rep's answer:
    setTimeout(() => {
      bubble.chat.addMessage({
        type: 'incoming',
        sender: 'Sam',
        html: 'Thanks! A team member will be right with you.'
      });
    }, 1500);
  });
</script>

Unread Messages

When an incoming message is added (or the model finishes a reply) while the chat is minimized, the unread attribute is set. The button then shows the "unread message" icon, wiggles, and pulses between the primary and the danger color. Opening the chat clears it. You can also set unread yourself, for example when your server tells you there is a new message. Users who prefer reduced motion get the color pulse without the wiggle.

<button id="receive">Receive a message</button>
<k-chat-bubble id="unreadBubble" heading="Support"></k-chat-bubble>
<script type="module">
  await customElements.whenDefined('k-chat-bubble');
  const bubble = document.getElementById('unreadBubble');
  await bubble.updateComplete;
  const receive = () => bubble.chat.addMessage({
    type: 'incoming',
    sender: 'Sam',
    html: 'Hi! Anything we can help with?'
  });
  // A message that arrives while the chat is minimized sets `unread`.
  receive();
  document.getElementById('receive').addEventListener('click', () => {
    bubble.hide();
    receive();
  });
  // Or set it yourself, e.g. when your server says there is a new message:
  // bubble.unread = true;
</script>

Position

The position attribute picks the corner: bottom right (the default), bottom left, top left or top right. At the top the popup opens below the button, and it lines up with the edge of the window the button is on. This one has no heading, so it has no header bar either.

<k-chat-bubble position="top left"></k-chat-bubble>

Full Screen

Add allow-fullscreen and a full screen icon appears at the top right of the popup (it makes the header bar show, even without a heading). Clicking it makes the popup as wide and tall as the window allows, with one --spacer of space around it, except for the corner of the round button, which stays free so the user can still minimize the chat. Click the icon again, or press Escape, to go back. With persistent-id the full screen state is kept when the page changes, like the open state. Open the chat below and try it; here it fills the dashed box, in your page it fills the window.

<k-chat-bubble heading="Support" allow-fullscreen></k-chat-bubble>

Custom Controls

Three slots take your own controls. controls-top is the header bar, next to the list and plus icons of the conversations. controls-side is a small slot above the Send button, and controls-bottom is a row at the very bottom. A slot takes no room until something is in it. Here the header gets an email button, the slot above Send gets a call button (a tel: link, so it phones support on a phone), and two quick replies go at the bottom. Give the buttons and links the no-btn class (and no-link for a link) so the page's own button and link styles step aside and they match the built-in icons. bubble.chat.send(text) sends a ready-made message.

<k-chat-bubble id="controlsBubble" heading="Support" persistent-id="docs-controls-bubble">
  <button slot="controls-top" class="no-btn" title="Email me this chat" aria-label="Email me this chat">
    <k-icon name="mail"></k-icon>
  </button>
  <a slot="controls-side" class="no-btn no-link" href="tel:+18005550123" title="Call support" aria-label="Call support">
    <k-icon name="call"></k-icon>
  </a>
  <button slot="controls-bottom" class="reply">Order status</button>
  <button slot="controls-bottom" class="reply">Talk to a person</button>
</k-chat-bubble>
<script type="module">
  await customElements.whenDefined('k-chat-bubble');
  const bubble = document.getElementById('controlsBubble');
  await bubble.updateComplete;
  bubble.querySelectorAll('.reply').forEach((button) => {
    // send(text) sends that text, as if the user had typed it
    button.addEventListener('click', () => bubble.chat.send(button.textContent));
  });
</script>

Saved Conversations

Add persistent-id and the conversations are saved in the browser, as with <k-chat persistent-id>. The first time the bubble is opened after a page load, and there are saved conversations, it lists them: click one to continue it, or start a new one. Each has three buttons: the pencil renames it (type a name and press Enter, Escape cancels), the arrow downloads it as a text file (the messages and, with debug, a record of what was sent to the model, its raw replies and the tool calls, handy when something goes wrong), and the bin deletes it (a confirmation dialog asks first). The list icon in the header brings the list back at any time, and the plus icon starts a new conversation. Send a message, reload the page, and open the bubble. Leave the bubble open and go to another page of these docs: it is still open, in the chat.

<k-chat-bubble heading="Support" persistent-id="support-bubble"></k-chat-bubble>

Connecting an LLM

The bubble does not care who answers: a customer service rep, your own server, or a cloud model called through a server. This is only the UI library, so what you write is the glue between the send event and your server, and these docs run on GitHub Pages and have no server. So the example below calls fetch('/api/chat') exactly as a real page would, and a small mock fetch (second card) answers with random markdown lorem ipsum after a random delay (and fails one time in eight). Delete the mock and point the URL at your server, and the page works for real.

Try it: send a message, minimize the chat while it types, and see the button ask for attention. The steps are the same for any backend:

  1. On send, show a placeholder from the other side with addMessage(). Mark it transient so it is not saved with the conversation.
  2. Ask your server with e.detail.markdown, the text the user wrote (and bubble.chat.conversationId if the server keeps the conversation).
  3. Show the answer by updating the placeholder with updateMessage(): html to show (through renderMarkdown if the answer is markdown), markdown for what the conversation is saved with, and transient: false so it is saved. The message is sanitized for you.
  4. Update the status of the user's message (e.detail.id) with updateMessage(id, { status }): read when answered, failed when not (with show-status the user sees it).
  5. Ask for attention with bubble.unread = true when the chat is minimized. A message added with addMessage() does it by itself, but finishing a placeholder is not a new message.

A real rep works the same way, without the placeholder: the answer comes in (from a websocket or by polling) and you call bubble.chat.addMessage({ type: 'incoming', sender: 'Sam', html }).

<k-chat-bubble id="cloudBubble" heading="Support" show-status="icons" persistent-id="cloud-demo" empty-message="Ask anything. A server answers."></k-chat-bubble>
<script type="module">
  import renderMarkdown from '/src/utils/renderMarkdown.js';
  await customElements.whenDefined('k-chat-bubble');
  const bubble = document.getElementById('cloudBubble');
  await bubble.updateComplete;
  bubble.addEventListener('send', async (e) => {
    // A placeholder while the server works. `transient` keeps it out of the saved conversation.
    const replyId = bubble.chat.addMessage({
      type: 'incoming',
      sender: 'Support',
      html: '<em>Typing...</em>',
      transient: true
    });
    try {
      const response = await fetch('/api/chat', {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({
          conversation: bubble.chat.conversationId,
          message: e.detail.markdown
        })
      });
      if (!response.ok) throw new Error(`The server answered ${response.status}`);
      const {
        reply
      } = await response.json();
      bubble.chat.updateMessage(replyId, {
        html: renderMarkdown(reply, {
          breaks: true
        }),
        markdown: reply,
        transient: false
      });
      bubble.chat.updateMessage(e.detail.id, {
        status: 'read'
      });
      // Finishing a placeholder does not count as a new message, so ask for attention yourself
      if (!bubble.open) bubble.unread = true;
    } catch (error) {
      bubble.chat.updateMessage(e.detail.id, {
        status: 'failed'
      });
      bubble.chat.updateMessage(replyId, {
        html: '<em>Sorry, no answer. Please try again.</em>'
      });
    }
  });
</script>

Built-in AI (Very Experimental)

VERY EXPERIMENTAL: DO NOT RELY ON THIS

Everything here that uses the browser's built-in AI (the Prompt API) is an experiment, and it is not useful yet. The model that ships with Chrome is tiny. In the author's testing it could not answer a single question correctly: it ignored its instructions, skipped tool calls, made up attributes and wrote wrong code. The code around it works (it sends messages, runs tools and shows replies), but do not expect correct answers, and do not put it in front of your users.

It needs a recent desktop Chrome with the on-device model available, and the first message downloads the model. This does not affect the rest of the chat: a chat you connect to a person, a server or a cloud model works as usual.

With prompt-api the chat inside is answered by the browser's built-in language model, exactly as in the Chat docs: the value is the file (or files) holding the system prompt, and promptTools gives the model functions to call. Try asking it to switch to dark mode.

Very experimental, and not useful yet: in the author's testing the browser's built-in AI could not answer a single question correctly. See the warning at the top of this section. 
<k-chat-bubble id="assistantBubble" heading="Assistant" prompt-api="/media/kempo-helper.md /overview.txt" persistent-id="assistant-bubble" show-status="icons"></k-chat-bubble>
<script type="module">
  import {
    setTheme
  } from '/src/utils/theme.js';
  await customElements.whenDefined('k-chat-bubble');
  document.getElementById('assistantBubble').promptTools = [{
    name: 'setTheme',
    description: 'Changes the color theme of this page',
    inputSchema: {
      type: 'object',
      properties: {
        theme: {
          type: 'string',
          enum: ['light', 'dark', 'auto']
        }
      },
      required: ['theme']
    },
    execute: ({
      theme
    }) => {
      setTheme(theme);
      return `The theme is now ${theme}.`;
    }
  }];
</script>

JavaScript Reference

Constructor

Extends ShadowComponent
new ChatBubble()

Requirements

  • ShadowComponent
  • Chat (the popup)
  • Icon (the chat_bubble, mark_chat_unread, chevron, format_list_bulleted, add and delete icons)

Properties

position: String

"bottom right" (default), "bottom left", "top left" or "top right". Syncs to position attribute.

open: Boolean

Whether the chat popup is open. With persistent-id it is also remembered for the browser tab (in sessionStorage), so an open chat is still open, in the chat, when the user moves to another page, and starts closed in a new tab or visit. Syncs to open attribute.

allowFullscreen: Boolean

Puts a full screen icon in the popup's header (the header bar shows because of it). Syncs to allow-fullscreen attribute.

fullscreen: Boolean

Whether the popup fills the window (one --spacer from the edges, clear of the round button). Only works with allow-fullscreen. Syncs to fullscreen attribute.

unread: Boolean

Whether there is a message the user has not seen. While it is true and the chat is minimized the button wiggles and pulses. It is set when a message arrives while minimized, and cleared when the chat opens. Syncs to unread attribute.

debug: String

Records everything that happens with the model (the system prompt, what is sent, its raw replies, the tool calls and their results) with each conversation, see the chat's debug. The record goes into the file made by the export button of the conversation list. debug="console" also prints it to the console. Syncs to debug attribute.

emptyMessage: String

Text shown in the middle of the messages while there are none, such as Get help from the AI Assistant. Syncs to empty-message attribute. Passed to the chat. Not to be confused with placeholder, which is the text inside the message box.

input: String

What the user types in, as for <k-chat>. Default "markdown": a clean, growing message box whose text is markdown, with no tabs, toolbar or resize handle, which suits the small popup. Use "markdown-editor" (it then gets a compact toolbar), "html-editor" or "text" for the others.

heading: String

The title in the popup's header, and in the button's label for screen readers. Optional: with no heading, no controls-top content and no persistent-id (whose list and plus icons live in the header) the header bar is left out and the chat fills the popup.

promptApi: String, promptTools: Array, persistentId: String, placeholder: String, showStatus: String, enterNewline: Boolean, disabled: Boolean

Passed to the <k-chat> in the popup, where they work as described in its docs (attributes prompt-api, persistent-id, show-status and enter-newline). promptTools is a property only. For anything else, use bubble.chat.

chat: Chat (read-only)

The <k-chat> inside the popup. Use it to add messages (bubble.chat.addMessage()), read the conversation and call its other methods. It exists from the first render on (so await bubble.updateComplete before using it right after the page loads), also while the popup is minimized.

Slots

A slot takes no room until something is in it.

  • controls-top — the header bar, between the title and the built-in list and plus icons (which only show with persistent-id). Buttons and links with the no-btn class (no-link too, for a link) are styled to match them.
  • controls-side — a small slot beside the message box, above the Send button, for something like a call button. Passed to the chat's controls-side.
  • controls-bottom — a row at the very bottom, below the message box. Passed to the chat's controls-bottom.

Methods

downloadConversation(id): Promise<boolean>

Saves a conversation as a text file, what the export button of the conversation list does.

toggleFullscreen(): void

Enters or leaves full screen, when allow-fullscreen is set.

show(), hide(), toggle(): void

Open, minimize, or toggle the popup.

showConversations(): Promise<void>

Shows the list of saved conversations in the popup (what the list icon in the header does). Needs persistent-id.

Events

fullscreen-change

Fires when the popup enters or leaves full screen. detail contains { fullscreen }.

open, close

Fire when the popup opens or is minimized.

send, response, error, tool-call, message-add, conversation-change, conversation-save

The events of the <k-chat> inside, passed on with the same detail, so you can listen on the bubble. See the Chat events.

Accessibility

The button is a real button with an aria-label (Open Support, Minimize Support with a heading of Support, Open chat without one, and a note when there is an unread message) and aria-expanded. The popup is a dialog, the focus moves to the message box when it opens, and Escape leaves full screen, and then minimizes it and puts the focus back on the button.
